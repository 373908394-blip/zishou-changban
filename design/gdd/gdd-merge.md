# GDD · 文字合成（gdd-merge）

> 模块：征兵抽字 / 同字升阶 / 名将对子组合武将
> 状态：垂直切片 MUST 范围（同字升阶 1→3 阶 + 赵云配方；张飞/黄忠配方预留接口）

---

## 1. 抽字池（征兵 Recruit）

- 征兵消耗 `RECRUIT_COST = 3` 馒头（见 overview），随机抽 1 个汉字单位入"手牌"。
- 抽字池与权重（垂直切片）：

| 字符 | 类别 | 权重 weight | 说明 |
|------|------|-------------|------|
| 刀 | 基础 | 22 | 近战 |
| 枪 | 基础 | 20 | 长矛近战 |
| 弓 | 基础 | 18 | 远程 |
| 骑 | 基础 | 16 | 骑兵 |
| 赵 | 名碎片 | 6 | 凑赵云 |
| 云 | 名碎片 | 6 | 凑赵云 |
| 张 | 名碎片 | 3 | 预留（目标版） |
| 飞 | 名碎片 | 3 | 预留 |
| 黄 | 名碎片 | 2 | 预留 |
| 忠 | 名碎片 | 2 | 预留 |

- 抽字算法：按 weight 归一化做加权随机；保证基础兵种占主流（上手快），名碎片低频（合成有"收集感"）。
- 名碎片在切片中**仅参与赵云配方**；张/飞/黄/忠抽到后暂作"可合成占位"，目标版接武将。

## 2. 合成操作（交互）

- 拖拽一个单位 A 到另一个单位 B 上释放 → 触发 `tryMerge(A, B)`。
- 合并判定优先级：**配方组合 > 同字升阶 > 失败**。
- 合并后 A 销毁、B 变为结果（或升阶），占用 B 的原网格格。

## 3. 合成规则一：同字升阶（Tier Up）

- 条件：`A.char === B.char` 且 `A.category==='basic'` 且 `B.tier < MAX_TIER(3)` 且 `A.tier === B.tier`。
- 结果：B 的 `tier + 1`，属性按阶乘缩放（见 units-monsters 表 `TIER_MULT`）。
- 跨阶不允许直接合并（如 tier1 + tier2 不合，需先各自升阶）。
- 例：`刀(t1) + 刀(t1) → 刀(t2)`；`刀(t2) + 刀(t2) → 刀(t3)`。

## 4. 合成规则二：名将对子组合（Hero Recipe）

- 条件：`(A.char, B.char)` 命中配方表。
- 结果：在 B 的网格格生成对应武将单位，A、B 均销毁。

```js
const RECIPES = {
  "赵+云": "zhaoyun",   // 赵云
  "云+赵": "zhaoyun",
  // 目标版扩展：
  "张+飞": "zhangfei",
  "飞+张": "zhangfei",
  "黄+忠": "huangzhong",
  "忠+黄": "huangzhong"
};
```

- 武将单位属性见 units-monsters 表；技能见 skill-vfx 表。
- 合成武将**不消耗馒头**（仅消耗抽到/拥有的名碎片），降低门槛。

## 5. 合成失败处理

- 不满足上述任一条 → 不合并，A 弹回原格，播放"墨点散开"否定反馈（短震 + 灰闪）。
- 占位/未解锁配方（如张+飞在切片中）：视为失败，提示"暂未解锁"。

## 6. 数据模型（工程接口）

```js
// unit 实例
{
  uid, char, name, category:'basic'|'hero',
  tier: 1..3,                 // hero 固定 tier=3
  col, row,                   // 网格坐标（hero 同）
  // 运行期派生（来自 base def * tier mult）
  damage, range, atkInterval, type, projectile, skillId|null,
  atkTimer, animState
}
```

## 7. 平衡校验（防主导策略）

- 同字升阶是"稳定数值流"；武将组合是"技能爆发流"。二者成本不同（升阶只花馒头；武将花稀有名碎片），**不互相碾压**——武将强但难凑，升阶易但需时间/馒头，形成 build 双轨。
- 若实测武将过强 → 上调名碎片权重外的获取难度或下调技能倍率（见 skill-vfx）。
